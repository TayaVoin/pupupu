# Аудит проекта Cell Monitor Server

Дата аудита: 2026-06-07.

## Итог

Проект представляет собой собираемый учебный C++ desktop-прототип сервера и
просмотрщика измерений мобильной сети. Чистая Release-сборка target `server` на
dev environment проходит без ошибок. Реальный runtime с Android, PostgreSQL,
ZMQ, OpenGL GUI и сетью OSM в рамках этого аудита не запускался: по правилам
проекта он проверяется на stage environment.

После аудита от 2026-06-04 код заметно изменился. Добавлены поля RSRQ, RSSI,
Altitude и EARFCN для карты, выбор критерия и EARFCN в GUI, фоновый расчет IDW и
защита от повторной постановки части запросов тайлов. Поэтому несколько старых
замечаний больше не актуальны в прежней формулировке.

При этом проект пока нельзя считать полностью соответствующим исходному
заданию. Наиболее существенные причины:

- схема PostgreSQL не согласована с запросом загрузки RSSI;
- в БД, графиках, текущем GUI и карте используется только первая LTE-сота;
- live RSSI на карте подменяется значением RSRP;
- координаты карты смешивают Web Mercator и линейный расчет по градусам;
- фоновый IDW содержит ошибки invalidation и отрисовки пустых областей;
- GSM, NR и traffic объявлены в модели, но не разбираются из JSON;
- runtime-поведение на stage не подтверждено.

## Проверка сборки

Сборка выполнялась вне репозитория:

```bash
rm -rf /private/tmp/pupupu-cmake-audit
cmake -S . -B /private/tmp/pupupu-cmake-audit \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_EXPORT_COMPILE_COMMANDS=ON
cmake --build /private/tmp/pupupu-cmake-audit \
  --target server --clean-first --parallel 4
```

Результат:

```text
[100%] Built target server
```

Ошибок конфигурации, компиляции и линковки нет. Остались предупреждения:

- deprecated `sprintf` внутри vendored `third_party/stb/stb_image_write.h`;
- неиспользуемое приватное поле `ServerCore::m_historyVersion`;
- линкер игнорирует повторное подключение `libimgui.a`.

## Архитектура и поток данных

### Запуск

`src/main.cpp` инициализирует SDL2, OpenGL/GLEW, ImGui и ImPlot, создает
`ServerCore`, `MapManager` и `GuiManager`, запускает ZMQ-сервер, синхронно
загружает исторические точки из PostgreSQL и входит в GUI-цикл.

### Прием данных

`ServerCore` поднимает ZMQ REP-сокет на `tcp://*:5000`. Для каждого сообщения:

1. JSON преобразуется в `Measurement`.
2. Измерение добавляется в память.
3. Перестраивается кэш RSRP для графика.
4. Первая LTE-сота записывается в PostgreSQL.
5. Сокращенная запись добавляется в `measurements.json`.
6. Клиенту отправляется строка `OK`.

Прием работает в отдельном потоке, но запись в БД и JSON выполняется в том же
потоке последовательно с обработкой запроса.

### GUI

`GuiManager` отображает:

- последние координаты и часть параметров первой LTE-соты;
- один график RSRP первой LTE-соты;
- число значений в кэше графика;
- контролы zoom, heatmap, критерия, радиуса и EARFCN;
- OSM-карту, текущую точку, исторические точки и heatmap.

### Карта и heatmap

`MapManager` содержит два фоновых потока:

- tile worker читает тайлы с диска или загружает их через curl;
- heatmap worker вычисляет IDW в CPU-буфер.

OpenGL-текстуры создаются в GUI-потоке. Heatmap рассчитывается по выбранному
критерию RSRP, RSRQ, RSSI или Altitude и предварительно фильтруется по EARFCN.

## Актуальные проблемы

### Критичные для задания

1. `createTable()` не создает `lte_rssi`, но `loadAggregatedPoints()` выполняет
   `SELECT lte_rssi`. На новой БД загрузка исторических точек завершится
   SQL-ошибкой. INSERT также не сохраняет RSSI.
2. При нескольких LTE-сотах в PostgreSQL, JSON backup, current GUI, plot и map
   попадает только `lteCells[0]`. Это противоречит заданию по PCI и EARFCN.
3. Для текущей точки `GuiManager` записывает в `MapPoint::rssi` значение RSRP,
   хотя `LteCellDto::rssi` уже существует.
4. Графики не покрывают RSSI и SINR/RSSNR и не разделяются по PCI.
5. Heatmap сохраняется не в требуемую build-директорию, а разные критерии,
   EARFCN и области перезаписывают один файл одного zoom.

### Корректность карты и IDW

- OSM-тайлы вычисляются по Web Mercator, но позиционирование тайлов, точек,
  pan, zoom и проверка границ выполняются линейно по широте/долготе.
- При отсутствии соседей IDW присваивает `-140`, после чего рисует непрозрачный
  красный пиксель вместо прозрачного.
- Веса всегда равны `1 / d^2`; объявленный `idwPower` не используется.
- Hash heatmap учитывает размер массива и координаты только первой точки.
  Изменение остальных значений может не вызвать пересчет.
- Готовая heatmap повторно загружается через `glTexImage2D` каждый кадр.

### Надежность и потоки

- `getCachedRsrpHistory()` возвращает ссылку после освобождения mutex.
- `serverLoop()` читает `m_history` для построения plot-cache без `m_mutex`.
- Tile worker спит 100 мс, удерживая `m_queueMutex`.
- Неудачный tile request остается в `m_requestedTiles` и не запрашивается снова.
- `downloadTile()` при HTTP 418 возвращается до `curl_easy_cleanup()`.
- `exit(0)` из меню обходит нормальный shutdown.
- GL-текстуры тайлов и heatmap не очищаются перед уничтожением GL context.

### Данные и БД

- `parseJson()` подавляет исключения и возвращает пустое измерение.
- GSM, NR и traffic не разбираются.
- JSON backup содержит только timestamp, lat, lon и RSRP первой соты.
- `deviceIdEsc[256]` не рассчитан на произвольную длину device ID.
- Пароль PostgreSQL хранится в `include/Config.h`.
- Комментарий обещает индекс по timestamp, но код индекс не создает.

## Пересмотр прошлого аудита

### Исправлено или потеряло актуальность

- Проект собирается.
- `MapPoint` и `AggregatedPoint` теперь содержат четыре критерия и EARFCN.
- Выбор критерия реально влияет на значение IDW.
- Heatmap больше не рассчитывается непосредственно в GUI-потоке каждый кадр.
- Есть фильтр EARFCN.
- Есть набор `m_requestedTiles`, сокращающий повторную постановку запросов.
- GUI больше не копирует полную `m_history` каждый кадр для графика.

### Исправлено частично

- Фоновый кэш heatmap введен, но invalidation и публикация результата требуют
  исправления.
- Дубликаты tile requests блокируются, но ошибки загрузки делают блокировку
  постоянной.
- История для графика кэшируется, но доступ к кэшу потоконебезопасен.
- Модель содержит RSSI, но DB pipeline и live map используют его неправильно.
- EARFCN поддержан фильтром, но не полноценным разделением данных и файлов.

### Остается актуальным

- неправильная геометрия карты;
- потеря всех LTE-сот кроме первой;
- неполные графики;
- неполный JSON parser;
- hardcoded DB credentials;
- синхронная загрузка истории при старте;
- отсутствие освобождения GL-текстур;
- некорректный выход через `exit(0)`.

## Вывод

Код достиг состояния чистой сборки и содержит каркас большинства требуемых
подсистем. Основная работа теперь состоит не в добавлении новых окон или
потоков, а в доведении сквозного data flow до согласованного состояния:
Android JSON -> все LTE-соты -> PostgreSQL/JSON -> PCI-графики -> корректная
Web Mercator карта -> IDW по реальным критериям и EARFCN.

Приоритетный план исправлений находится в `ssot/remediation-plan.md`.
