# Отчет о реализации Cell Monitor Server

Дата составления: 2026-06-07.

## 1. Назначение работы

В проекте разработано desktop-приложение на C++ для приема измерений мобильной
сети от Android-устройства, их сохранения и отображения. Сервер объединяет ZMQ,
JSON, PostgreSQL, ImGui/ImPlot, OpenStreetMap и расчет тепловой карты методом
обратных взвешенных расстояний (IDW).

Android-приложение в данном репозитории отсутствует. Отчет описывает серверную
часть, находящуюся в `src/` и `include/`.

## 2. Использованные технологии

- C++17 и CMake;
- ZeroMQ/cppzmq для обмена сообщениями;
- nlohmann/json для разбора JSON;
- PostgreSQL/libpq для хранения измерений;
- SDL2, OpenGL и GLEW для окна и графики;
- Dear ImGui и ImPlot для интерфейса и графиков;
- libcurl и stb для загрузки и декодирования PNG-тайлов;
- OpenStreetMap как источник карты;
- `std::thread`, mutex и atomic для фоновых операций.

## 3. Архитектура

Приложение разделено на три основные части.

`ServerCore` отвечает за ZMQ, JSON, историю измерений, PostgreSQL и резервный
JSON-файл.

`GuiManager` формирует окна с текущими данными, статистикой, графиком и
настройками карты.

`MapManager` рассчитывает координаты тайлов, загружает и кэширует OSM PNG,
создает OpenGL-текстуры, рисует точки и формирует heatmap.

`main.cpp` инициализирует библиотеки, связывает эти компоненты и выполняет
главный event/render loop.

## 4. Прием данных по ZMQ

Сервер создает REP-сокет и привязывает его к:

```text
tcp://*:5000
```

При поступлении сообщения сервер:

1. принимает byte payload;
2. преобразует его в строку JSON;
3. формирует объект `Measurement`;
4. сохраняет измерение в памяти, БД и JSON-файл;
5. отправляет клиенту ответ `OK`.

Timeout приема позволяет серверному потоку периодически проверять флаг
завершения и штатно останавливаться.

Реализованный JSON parser читает:

- location: latitude, longitude, altitude, timestamp, speed, accuracy;
- LTE: band, EARFCN, MCC, MNC, PCI, TAC, RSRP, RSRQ, RSSI, RSSNR, CQI и
  Timing Advance;
- deviceId.

Структуры GSM, NR и traffic подготовлены в модели, но их parser пока не
реализован.

## 5. Хранение данных

При запуске выполняется подключение к PostgreSQL и создается таблица
`measurements`, если она отсутствует.

В текущую запись включаются:

- время и координаты;
- altitude, accuracy и speed;
- device ID;
- PCI, RSRP, RSRQ, RSSNR, EARFCN и TAC первой LTE-соты;
- время приема сервером.

Дополнительно приложение записывает строку JSONL в `measurements.json`. Это
резервный журнал с сокращенным набором полей.

Исторические точки загружаются из PostgreSQL при запуске. Для ограничения
объема выбираются последние записи и используется каждая десятая точка, не
более 5000 точек для карты.

Ограничение реализации: RSSI пока не согласован со схемой таблицы, а при
нескольких LTE-сотах сохраняется только первая.

## 6. Пользовательский интерфейс

GUI состоит из следующих окон:

- `Current Data`: device ID, координаты, altitude, accuracy, PCI, RSRP, RSRQ и
  RSSNR;
- `Signal Plots`: временной график RSRP;
- `Statistics`: количество значений графика;
- `Map Controls`: zoom, включение heatmap, критерий, радиус и EARFCN filter;
- `OSM Map`: карта, heatmap, текущая и исторические точки.

Для графика используется ImPlot. Кэш значений RSRP обновляется при поступлении
нового сообщения, поэтому GUI не копирует полную историю в каждом кадре.

Ограничение реализации: график строится только по RSRP первой LTE-соты. Линии
RSSI/SINR и отдельные серии по PCI еще не выполнены.

## 7. OpenStreetMap

Координаты центра переводятся в номера OSM-тайлов. Количество запрашиваемых
тайлов зависит от текущего размера окна.

Tile worker выполняет загрузку асинхронно:

1. проверяет PNG в `tile_cache/zoom/x/y.png`;
2. при отсутствии обращается к `tile.openstreetmap.org` через curl;
3. декодирует PNG в RGBA;
4. сохраняет файл на диск;
5. передает данные GUI-потоку для создания OpenGL-текстуры.

Набор requested tile keys уменьшает число одинаковых запросов, пока тайл
ожидает загрузки.

Карта поддерживает перетаскивание мышью и изменение zoom колесом. При получении
первой валидной точки центр карты меняется на координаты измерения.

Ограничение реализации: экранные координаты пока считаются линейно по градусам,
а тайлы используют Web Mercator. Поэтому точное центрирование и навигация
требуют исправления.

## 8. Тепловая карта IDW

В интерфейсе можно выбрать:

- RSRP;
- RSRQ;
- RSSI;
- Altitude;
- радиус интерполяции от 10 до 40 метров;
- конкретный EARFCN или все EARFCN.

Перед вычислением точки фильтруются по EARFCN. Для каждого пикселя перебираются
экспериментальные точки внутри заданного радиуса. Вес вычисляется по формуле:

```text
w = 1 / d^2
value = sum(w * measured_value) / sum(w)
```

Расчет выполняется в отдельном heatmap worker, а не в GUI-потоке. Worker
формирует RGBA-буфер, после чего GUI загружает его в OpenGL. PNG сохраняется в:

```text
heatmap_cache/heatmap_zoom_<zoom>.png
```

Цвет строится градиентом красный -> желтый -> зеленый. Для каждого критерия
задан свой ожидаемый диапазон.

Ограничения реализации:

- пустые области сейчас окрашиваются вместо прозрачности;
- live RSSI подменяется RSRP;
- кэш не гарантирует invalidation при любом изменении данных;
- имя файла не разделяет критерии, EARFCN и области;
- путь не соответствует требованию сохранять heatmap внутри build.

## 9. Фоновая работа

В приложении используются отдельные потоки:

- ZMQ server thread;
- OSM tile worker;
- heatmap worker.

Это предотвращает прямое выполнение сетевой загрузки и IDW в render loop.
Между потоками используются mutex и atomic flags.

Текущая реализация требует дополнительной работы над condition variables,
публикацией immutable snapshots и корректным shutdown. Подробности приведены в
аудите и remediation plan.

## 10. Проверка сборки

На dev environment выполнена чистая Release-сборка вне репозитория:

```bash
cmake -S . -B /private/tmp/pupupu-cmake-audit \
  -DCMAKE_BUILD_TYPE=Release
cmake --build /private/tmp/pupupu-cmake-audit \
  --target server --clean-first --parallel 4
```

Результат:

```text
[100%] Built target server
```

Сборка подтверждает согласованность C++ target и зависимостей на dev
environment. Она не подтверждает взаимодействие с Android, доступность
PostgreSQL, сетевую загрузку OSM и визуальную корректность GUI.

## 11. Итог

В проекте реализован работающий по структуре серверный прототип, объединяющий
все основные технологии задания: ZMQ, JSON, PostgreSQL, ImGui/ImPlot, OSM и
IDW. Проект компилируется, карта и heatmap вынесены в отдельные компоненты, а
дорогой расчет IDW выполняется в фоне.

Для полного соответствия заданию необходимо довести сквозную поддержку
нескольких LTE-сот, графики по PCI, RSSI в БД, корректную Web Mercator
геометрию, invalidation heatmap и stage runtime-проверку.
